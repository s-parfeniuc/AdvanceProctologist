# Chapter 1 – Introduction to Advanced Programming

## 1.1 Course Overview and Objectives
The course *Advanced Programming* is designed to explore programming not only as a practice of writing code but, more importantly, as the ability to **understand, analyze, and critically evaluate code** produced by others—including artificial intelligence (AI) systems. As Professor Cisternino emphasized, the central challenge for the modern programmer is not simply *coding*, but *reading and reasoning about code* that increasingly originates from automated tools【10†Trascrizione】.

This approach reflects the changing professional landscape: software engineers of the near future will be expected to oversee, validate, and refine codebases generated by AI models such as GitHub Copilot, ChatGPT, or Google Gemini. The aim is to prepare students to take responsibility for evaluating correctness, efficiency, and security in this new programming paradigm.

## 1.2 The Role of Artificial Intelligence in Programming
Historically, programming languages were conceived as formal, human-readable abstractions over machine code. Today, AI has become capable of generating syntactically and semantically correct programs. However, while most generated code now compiles and executes correctly, its **behavioral correctness** is not guaranteed. This introduces risks, including hidden bugs, unsafe practices, or even malicious backdoors【10†Trascrizione】.

Two key issues emerge:
- **Probabilistic Generation**: Large Language Models (LLMs) generate output by sampling probable continuations of text. This method introduces creativity and variety but also the risk of *hallucinations* (incorrect or misleading outputs).
- **Security Concerns**: AI-generated code may inadvertently (or deliberately, if manipulated) contain vulnerabilities. Historical examples such as backdoors in open-source projects illustrate how dangerous undetected flaws can be.

Thus, advanced programming today requires developing skills not only in writing but in **auditing and reasoning about code produced by non-human agents**.

## 1.3 Historical and Conceptual Context
The course introduction invoked Alan Turing’s early speculations about machine intelligence. Turing predicted that, once machines became sufficiently advanced, they would not merely execute human-written instructions but begin to generate their own “tables”—early metaphors for programs. This prophecy resonates strongly today, where AI systems autonomously produce code that must still be critically assessed by human programmers【10†Trascrizione】.

The analogy extends into questions of responsibility. Just as society debates accountability in self-driving cars (programmer, manufacturer, or AI system), so too must computer scientists ask: **who is responsible for the consequences of AI-generated software?** This ethical dimension underpins much of the course philosophy.

## 1.4 Teaching Methodology
The teaching style of *Advanced Programming* emphasizes interactivity and experimentation. Classes will include both theoretical and practical sessions:
- **Theoretical Foundations**: syntax, semantics, type systems, closures, and runtime environments.
- **Practical Exploration**: using AI models (e.g., GPT, Copilot, Claude, Gemini) to generate and analyze code.
- **Critical Engagement**: students will be encouraged to test AI output, identify critical sections of code, and employ systematic strategies (such as unit testing and cross-model verification) to ensure correctness【10†Trascrizione】.

Importantly, students are considered part of an *experiment*: this is the first iteration of the redesigned course, and as such, flexibility and adaptation will be part of the learning experience.

The generated program included zooming and graphical manipulation, demonstrating both the efficiency and ambiguity of natural-language prompts. - **3D Flight Simulator**: As a second example, the AI was prompted to create a simple 3D airplane simulator with balloon-popping mechanics. These examples underline why reviewing AI-generated code is both essential and complex.

## 1.6 Probabilistic Outputs and LLM Behavior
One key feature of Large Language Models is their **non-deterministic generation process**. Unlike traditional compilers, which produce identical results given the same input, LLMs may generate different outputs even when prompted with the same text. This variability arises from the sampling strategy used during text generation.

At each step, the model computes a probability distribution over possible next tokens. By default, selecting only the *most probable token* at each step leads to repetitive and often unhelpful text. To avoid this, a randomness parameter known as **temperature** is applied:
- **Low temperature (≈0)**: the model becomes more deterministic, consistently choosing high-probability tokens. Useful for tasks requiring precision but may reduce creativity.
- **High temperature (>1)**: the model explores less probable tokens, increasing diversity in output but also raising the risk of incoherence or error.

In programming contexts, this trade-off is crucial. A low temperature setting may yield safer, more consistent code, while higher temperatures might introduce novel but potentially flawed solutions. Hence, developers must carefully balance determinism and creativity when using AI to generate or refactor software.

## 1.7 Key Concepts Preview
Among the fundamental concepts introduced were:
- **Lexical Closures**: functions retaining access to their defining environment even after that environment has been exited.
- **Scoping and Semantics**: the principle that code behavior should be derivable from its written text, a foundational pillar of programming language design.
- **Programming Language Families**: languages evolve in lineages (e.g., C → C++ → Java; Lisp → Scheme → Haskell), and recognizing shared structures helps in reasoning about unfamiliar syntax.
- **Multiplicity of Languages**: Drawing on Douglas Hofstadter’s *Gödel, Escher, Bach*, the professor compared programming languages to musical keys. Just as different keys in music make some passages easier to perform and interpret, different programming languages are more suitable for different classes of problems. It would be “stupid,” he argued, to insist on only one language, just as it would be absurd to write all music in a single key【10†Trascrizione】.

## 1.8 Course Structure and Examination
The syllabus will cover topics such as:
- Language evaluation models
- Runtime systems (e.g., JVM, LLVM, command-line runtimes)
- Memory management
- Type systems
- Closures and functional programming
- Object-oriented paradigms
- Asynchronous programming
- Toolchains (e.g., Git, IDEs, AI-assisted refactoring)

The **final exam** will consist of an **individual project** requiring students to:
1. Explore an unfamiliar programming language or codebase.
2. Use AI tools to assist in analysis and implementation.
3. Critically evaluate AI-generated results, providing arguments and evidence for correctness or identifying flaws.

This project will be followed by an oral examination.

## 1.9 Conclusion
The first lecture established the central theme of *Advanced Programming*: in the era of AI, programming is less about typing instructions and more about **interpreting, validating, and taking responsibility for code produced by intelligent systems**. This shift demands strong theoretical foundations, practical familiarity with AI tools, and above all, a critical mindset that balances trust and skepticism.

As the professor noted, *“it is pointless to ask you to write programs, because you will anyway use AI. What matters is whether you can evaluate the code it produces.”*【10†Trascrizione】
